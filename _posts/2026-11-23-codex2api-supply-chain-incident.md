---
title: "Codex2API 疑似供应链投毒：相关版本需要紧急排查"
date: 2026-11-23
---

2026 年 11 月 23 日，开源项目 **Codex2API** 被曝出严重的供应链安全事件。根据项目 Issue 和第三方独立复盘，攻击者疑似利用维护者账号凭据，通过异常 Tag 触发 Release 工作流，发布了带有后门的二进制程序。

## 涉及哪些版本？

公开报告指出，以下版本存在风险：

- **v3.1.10**：加入带 Token 校验的远程 Shell 命令执行接口。
- **v3.1.11**：移除鉴权，形成未授权远程命令执行能力。
- **v3.1.12**：进一步涉及环境变量读取、任意 SQL 执行和 TCP 连接等能力。

独立复盘还称，恶意 GitHub Actions 工作流可能读取并外传仓库中的 Secrets，并扩散到同一账号下的其他仓库。报告提及 16 项 Secrets 和至少 21 个仓库；这些数量属于第三方复盘披露的范围，并不代表每项凭据都已证实遭到滥用。

## 需要注意什么？

如果你下载、运行或更新过上述版本，建议立即：

1. 停止运行可疑二进制，不要继续使用在线更新。
2. 在干净环境回退到报告确认的安全版本 **v3.1.9**；如果怀疑主机已被执行过命令，不要只覆盖旧程序。
3. 轮换应用可读取的 API Key、数据库密码、Token、SSH Key 和 GitHub 凭据。
4. 检查服务器访问日志、异常进程和外连记录，特别留意报告提到的 `/i674` 路径。
5. 检查 GitHub Actions、异常 Tag、工作流运行记录，以及同一账号下的其他仓库。

**Docker 镜像需要区别对待：** 独立复盘称，核查时 GHCR 相关标签已重新指向 3.1.9，且 3.1.11、3.1.12 镜像未成功发布。因此，不能简单认定所有 Docker 镜像都已感染，应该结合拉取时间、镜像摘要和部署记录判断。
